# Skill评估与改进

先读 [评估入口](../../../workflow-evaluation/README.md)、[详细步骤](../../../workflow-evaluation/evaluation-guide.md) 和 [评分标准](../../../workflow-evaluation/rubrics/scoring.md)。只在用户请求评估/改进时执行，不在普通需求中自动增加评估流程。

## 运行

1. 固定技能文件、项目规则、任务场景、模型/推理设置和工具条件；记录版本。技能效果与模型效果不要同时改变。
2. 选择与本次修改相关的scenarios和未参与调优的保留场景，在独立临时工作区提供原始任务及模拟/合成依赖。向被测执行者只提供任务，不泄露评分答案。
3. 有可用且获准的独立执行者时运行任务；否则准备输入包/命令与待执行记录，不伪造执行。不要将评价工作写进用户业务仓库，不访问线上或发真实外部消息。
4. 保存可检查的任务产物、命令结果、关键决策和差异。由未负责本次答案生成的评审者对照rubrics判断；涉及产品偏好由用户确认。自动脚本只负责计算，不自行判定语义。
5. 按scorecard填写实际分数、证据、致命问题和缺失信息，用score.py计算。没有证据不能打满；有缺失评估项则结果为incomplete。
6. 找到失败发生的步骤，先修完成条件、来源定位或说明；不马上新增Skill/审批/文件。每轮只改变一个可解释因素，再用相同任务与保留任务比较。

## 完成

报告已跑场景、版本、样本量、逐项分数、关键失败、未执行和回归差异。评分阈值只是模板试运行建议，不自动成为业务发布门槛；不为提高分数修改题目预期或给被测执行者泄露答案。
