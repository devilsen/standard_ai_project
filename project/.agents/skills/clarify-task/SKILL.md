# 关键不确定性澄清

## 触发

目标、成功标准、范围、关键交互、数据/接口语义、成本/风险取舍仍不能确定，且不同选择会实质改变结果。可以从代码/文档/实验确认的事实先调查；日常可逆实现细节按已确认约定处理，不把所有编码选择都变成用户问卷。

## 执行

1. 读当前任务与相关正式来源，列出已确认内容、冲突证据和未确定的用户决定。
2. 在当前宿主技能目录定位并读取 `grill-me` 的SKILL.md，使用它分析，而不是只在回复中提到名称。依赖不存在时尝试宿主正常发现路径；仍不可用则明确缺失并暂停受影响决定，继续事实调查，不自行假定方向。
3. 每次聚焦一个最影响结果的问题；说明选项、推荐及理由、影响和仍可继续的工作。推荐不等于用户接受。
4. 用当前聊天的提问工具提问；在已绑定群按 [notify-project](../notify-project/SKILL.md) 同步同一个问题和问题编号，不制造两份不同问题。
5. 将等待状态、问题、首次提问时间、阻塞范围写回原task。只暂停依赖该决定的动作，继续无依赖工作；不以等待超时、无人反对或AI自信程度替代确认。
6. 用户长时间未答时，按已绑定提醒约定与实际调度能力提醒；未配置调度则如实说明没有后台计时。原问题未变化不循环刷屏。
7. 用户答复后核对身份和对应问题，写回原task与必要的PRD/契约，恢复受影响工作；同一决定不因换Skill或聊天重复问。

## 完成

相关决定有清楚来源，或者明确处于waiting并保留下一步。群里其他成员的意见不自动替代用户/已指定产品负责人的确认；消息回执不代表人已读或已同意。
