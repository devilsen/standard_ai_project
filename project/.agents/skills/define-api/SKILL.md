# 模块接口与边界

## 开始

读apiend、apiend/contracts和backend规则、交接设计、现有API调用方/实现、模型/迁移和测试。接口定义与示例维护在apiend/contracts，apiend展示读取同一份内容。设计阶段可先调查可行性；有关键产品歧义时不把某一猜测固定成契约。

## 步骤

1. 按用户操作列实际数据需求，标出已有接口可复用部分。完成条件：每个新增接口有明确用途与调用者，不按按钮机械建接口。
2. 定义本轮涉及的输入输出、类型、必填/可空、归属/权限、错误与示例；按需补任务状态、幂等、取消、分页、文件和兼容。完成条件：前端/mock/后端可以对同一例子得出同一结果。
3. 用最小调用链说明后端：业务状态所有者、事务边界、存储、外部服务、并发和失败恢复。比较复用与最小新增选择；若建议新表/服务/抽象，写当前问题和代价。完成条件：内部关键风险没有被“API定了”掩盖。
4. 更新OpenAPI与合成示例，让apiend从同一来源生成。核对现有调用者、旧数据和迁移影响。完成条件：契约可解析且示例有意义，文档不另写一套。
5. 在任务记录中引用契约和已确认决定；未决产品问题只阻断相关接口。准备mock/provider两侧的契约验证场景。

## 完成

说明接口变化、内部边界、兼容与验证方法。已有接口充分时引用并说明无需变更；不为了走流程新增端点或全面重构后端。
