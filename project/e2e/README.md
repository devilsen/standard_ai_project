# 浏览器与流程测试

这里使用 Playwright 检查用户操作、页面跳转、异常恢复和最终结果。

## 关键入口

- [测试计划模板](../docs/workflow/templates/test-plan.md)：选择测试范围。
- [用户案例](../cases/README.md)：真实流程的输入与预期。
- [本目录规则](AGENTS.md)。

## 怎么用

先用 designend 和 mock 验证交互，再在测试环境用真实前后端验证业务案例并修复。用户确认测试版本后，发布staging并核验实际关键路径。分别记录结果与替身范围。

测试命令与环境写入任务记录。页面打开、按钮可见或 mock 通过，都不能替代真实业务完成。
