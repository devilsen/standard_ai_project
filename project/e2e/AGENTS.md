# 浏览器与流程测试

- 使用 Playwright 执行浏览器测试；它是工具，mock E2E 和真实 E2E 是不同测试范围，不另建三个重复测试体系。
- 每条测试关联确认的行为或 case，断言用户可观察的结果。避免以私有 state、CSS 类名或当前快照决定正确性。
- 设计测试可使用 mockend，覆盖本次模块的导航、状态、异常与恢复；必须明确这是 mock 测试。
- 真实 E2E 走正式 frontend、真实后端及所声明的依赖；任何替身、人工预置和跳过步骤都报告。
- 本轮真实case和相关回归先在测试环境完成；失败修复后重测受影响项。用户明确确认该版本后才发布staging，再核验实际版本与关键业务路径。自动测试通过不替代用户确认，也不要求无差别重跑全套用例。
- UI 200、按钮可见、任务 queued 或文件存在均不能单独证明业务完成；按 case 核验最终内容与可用性。
- 选择稳定的可访问名称/role；截图用于视觉变化检查，不把自动截图相等当作产品批准。
- 不为测试任意重跑/删除用户真实任务。优先隔离合成数据，清理仅针对本次创建内容。
- 不放宽断言、吞错或增加重试来制造通过；先报告失败原因与影响。
