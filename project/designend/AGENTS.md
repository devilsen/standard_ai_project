# 产品设计环境

## 职责

- 独立维护页面、交互与样式，用于产品增量设计和交接；只连接 mockend 或本地模拟服务。
- 记录底稿对应的 frontend 上线提交。不得直接修改正式 frontend 来完成产品设计。
- 新设计通过当前设计分支和预览交付；PRD 与界面对应同一次交接提交。

## 设计交付

- 每个新增/改变的操作都说明触发条件、点击结果、跳转位置、显示内容、失败恢复及刷新/返回行为；对当前需求不适用的部分写明即可。
- 需要后端能力的操作用可执行 mock 模拟，不以死按钮代替逻辑完成；模拟与未决定事项在设计说明中可识别。
- 至少覆盖本次需求涉及的正常与关键异常场景，不要求每次穷举全站状态。
- 场景数据来自 mockend。原型局部状态可以留在页面，业务场景数据不得再维护一套隐藏常量。
- 沿用已上线底稿的组件和视觉约定；全局改变需要在变更说明中列出影响。

## 交接与底稿更新

- 交付界面、PRD、mock 场景入口、相对底稿的行为变化、未确定项和对应案例；使用 `docs/workflow/templates/design-handoff.md`。
- 交接后可继续下一轮设计，但明确其起点；研发不跟随未交接的最新文件漂移。
- 更新底稿前核对未交付设计并保留交接版本。同步来源必须是实际上线 frontend 提交，保留 mock 配置，不拷贝凭据和真实业务资料。
- 底稿同步后验证 mock 启动、主要路由、代表性状态与没有业务后端请求。
