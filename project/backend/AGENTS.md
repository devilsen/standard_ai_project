# 后端业务实现

## 结构

- 沿用现有框架与业务模块边界。路由处理 HTTP 转换，业务流程管理规则与状态，数据访问和外部调用各有明确归属。
- 为本次变化画清调用链、数据所有权、事务/并发边界和失败后的恢复方式。API 固定了对外合同，不等于内部设计已自动完成。
- SOLID/Clean 用来减少修改涉及的知识和依赖；没有真实变化需求时，不为每个类机械新增接口、仓储、工厂或一层透传。
- 不在后端新增未经确认的业务拦截，不能以“安全惯例”或“架构最佳实践”替代用户的产品决定。

## 实现与测试

- 每次选一条可观察行为：写失败测试并确认失败原因，做最小实现，运行相关检查，再继续下一条。
- 通过后检查职责、重复和依赖；必要的小重构保持行为测试为绿。跨模块重构单独说明范围。
- 单测验证业务规则；集成测试验证真实数据库约束/事务/迁移；外部对接用例验证实际协议和错误映射。
- 能使用真实本地组件的集成测试不用内部层层 mock。昂贵/远程服务可受控替换，但报告替换边界。
- 外部服务的部分成功、超时、重复/迟到响应根据本次契约处理，不自行推导成功或重发有副作用任务。
- 执行现有项目的实际测试命令；本模板不规定通用目录重构或部署方式。
