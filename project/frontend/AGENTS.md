# 正式前端

## 职责

- 实现任务中固定的界面与 PRD；连接真实后端。designend 是设计参考，不是可整目录覆盖正式代码的发布源。
- 修改前运行设计场景，核对每项操作、状态和跳转，再阅读现有正式实现。设计与 PRD 冲突时指出具体位置，不能自行选一个。
- 原型中的临时代码、延时、硬编码和 mock 状态不直接进入正式实现。

## 界面与边界

- 保留项目既有 `features/<domain>`、共享组件、HTTP client、设计变量和路由约定。
- 先找同类页面与组件；新增视觉样式优先局部作用域。改全局样式、导航或共享组件时说明受影响页面并回归。
- 页面不导入 designend/mockend 的业务实现；不以环境判断在正式页面内嵌设计场景。
- 不新增设计与 PRD 没有依据的按钮、必填项、预检、确认步骤或使用限制。
- 发现原型实现不合理时，可以改技术实现；改变用户可见行为前必须明确提出。

## 验证与交接

- 模块单测验证行为、状态和异常恢复；Playwright 覆盖确认的导航与代表性场景。
- 页面请求与 apiend/contracts 中的定义一致；真实 API 错误保留可理解的原因，不用假成功吞掉。
- 真实案例验证结果、视觉差异和未验证环境写入任务记录。设计截图相似不等于接口/业务正确。
- 执行任务记录中的实际命令；命令未登记时先从 package.json 和现有测试配置定位，再补入记录，不编造命令。
