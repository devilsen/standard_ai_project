# 接口契约

- 按业务模块维护 OpenAPI；字段类型、必填/可空、错误、状态与示例有唯一含义。
- 每项接口说明使用场景、调用方、权限及所属资源。输入输出来自确认的设计与 PRD。
- 对涉及的异步任务、上传、分页、取消、重复提交明确语义；不向无关接口添加这些机制。
- 错误区分输入错误、资源缺失、权限、冲突与外部依赖失败。业务状态不能仅靠 HTTP200 表达成功。
- 变更前检查实际调用者和历史数据；兼容变化与不兼容变化分别说明。不能因改了 schema 就假定数据库迁移已完成。
- 示例使用合成数据；前端/mock/后端以同一契约测试。上层apiend读取本目录生成展示，不另维护接口正文。
- 新接口是否必要、契约如何划分需结合现有后端能力判断；不按按钮数量机械生成接口。
