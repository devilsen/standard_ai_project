# 模块测试计划

先建立行为映射，再按切片逐条写测试与实现。避免把工具名称当成独立测试层级。

| 行为/依据 | 场景及输入 | 独立预期 | 最近可观察边界 | 测试方式 | 使用替身的范围 | 通过证据/未执行原因 |
|---|---|---|---|---|---|---|
| | | | | | | |

## 按本次风险选择覆盖

- 正常：用户主路径与最终结果。
- 空值/缺失：没有数据、文件缺失、尚无结果。
- 错误与恢复：本次相关的非法输入、网络错误、外部失败、重试/取消/刷新。
- 权限与归属：涉及身份或资源访问时覆盖。
- 并发与重复：涉及重复提交、迟到响应或并发写时覆盖。
- 历史与兼容：涉及旧数据、版本切换、schema/数据库迁移时覆盖。
- 视觉：同类页面、共享组件、键盘与适用屏宽；哪些需要产品人工判断。
- 产物：真实内容、来源、可打开/可下载、目标阅读器；不只检查文件存在。

## 各层证明什么

| 层级 | 主要目标 | 不能据此宣称 |
|---|---|---|
| 单测/组件 | 规则、状态、用户操作与错误呈现 | 真实网络/数据库/模型已通过 |
| 接口契约 | 请求响应、错误、schema与调用方一致 | 业务语义和真实外部服务一定正确 |
| 真实本地集成 | 数据库、存储、事务、外部适配协议 | 目标部署环境整条链路已通过 |
| Mock Playwright | designend导航、交互、场景与恢复 | 正式后端或真实模型已成功 |
| 真实E2E | 声明环境与依赖下的完整用户case | 未测试阅读器/其他样本也通过 |

## 环境与用户验收

- 测试环境入口、固定代码/制品版本、本轮case与回归范围：
- 测试失败后的修复及受影响项复测证据：
- 测试通过后飞书私聊的验收操作与预期、用户确认来源（引用task/delivery）：
- staging发布候选与已确认版本是否一致；行为变化的重新验证/确认：
- staging发布后需验证的真实关键路径、实际版本与结果：

测试环境通过后仍需用户明确确认才发布staging；按本轮风险选择检查，不因环境分阶段就重复全部测试。

## 预期变化

测试失败时先判断环境、实现还是原预期有误。修改预期需引用确认的需求变化或独立证据；保留原因，不能仅更新快照消除差异。
