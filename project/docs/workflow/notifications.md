# 项目群通知与等待提醒

## 接入一次，按范围持续使用

接入时明确项目、实际发送bot/公司身份、用户私聊接收者、默认群唯一chat_id与群名、授权事件和答复人。具体账号与群绑定保存在当前成员的私有配置中，仓库只保存引用；不能从cwd或同名群猜测客户/应用身份。

本轮用户已要求需求疑问和交付时在项目群通知，且允许长时间未回时提醒。实际群尚需指定和核验；这是接收者缺失，不是每条消息都需要重新授权。接入新群或扩大披露范围才重新澄清。模板包没有发送任何群消息。

用户进一步明确：测试环境通过后必须飞书通知本人验收，确认后才发布staging；发布收尾分别通知本人和默认群。此范围的两次通知是工作流必经步骤，不是可选提前播报。

## 默认目标与环境配置

使用 [项目配置示例](project-settings.example.json) 记录测试/staging环境、私有身份绑定引用、owner_recipient_ref和default_chat_ref。采用后保存项目实际配置；共享模板不填真实账号、群或凭据。null表示尚未绑定，不是已配置成功。

默认群在本项目内持续复用，每次发送不用重新问“发哪个群”；显式指定另一群只在该次授权范围覆盖，除非用户明确修改项目默认。客户/项目不同不能借用此绑定。发送时仍核验当前身份与精确接收者。

私聊与群分别记录事件状态和回执。某一路成功后只续办未完成的一路；超时未知按原请求查证，不盲目重发。无法发送私聊时明确报告，不能以@群成员替代已要求的私聊。

必须读取宿主当前 `feishu-messenger` 及其公司规则；它负责身份核验、准备请求、实际发送和回执。本项目只规定何时通知与内容边界，不另写一套飞书发送器。

## 阶段事件

测试验收通知是workflow第6步；最终交付通知是第9步，也是最后一步：用户确认测试版本→staging发布与验证→设计底稿同步及验证→交付记录→分别私聊用户和发默认群。设计评审消息按实际需要发送，不按内部小步骤播报。疑问、阻塞、失败和等待提醒仍及时发送。

| 事件 | 何时发送 | 消息必须说明 |
|---|---|---|
| 待决定/阻塞 | grill-me找到影响方向的问题，或真实依赖阻塞 | 同一个问题、选项与推荐、影响、可继续项 |
| 设计交接 | 可操作设计与PRD已经固定，可以开始评审 | 变化、预览/PRD、需确认位置、未决项 |
| 测试环境待用户验收 | 本轮开发修复与真实测试通过，必须私聊用户；默认群可同步摘要 | 测试入口/版本、验收操作与预期、PR/证据、仅测试可用/尚未发布staging、请明确确认 |
| 最终staging交付 | 用户确认后已发布并验证、底稿/记录完成，最后分别私聊用户与默认群 | 实际staging版本/入口、用户确认依据、PR、验证范围、底稿结果与遗留项 |
| 后续验收结果 | 最终通知后用户确实确认了验收，且需补充该实质结果 | 真实确认来源与剩余项；不把后续确认当作发送前已通过 |
| 实质失败 | 对交付有影响的失败或状态变化 | 失败事实、影响、处理/所需决定；不能伪报完成 |

同一时刻的测试通过与PR准备好合并在待验收消息中，不能作为最终staging交付；没有新结果、风险或用户动作不刷屏。测试验收未确认时保持waiting，群消息接受/已读不能解锁发布。仅代码/PR交付范围不自动触发上线；按实际范围报告。

## 长时间没有回复

- 关键问题出现时即可发群消息，不必先等很久。
- 等待提醒时间在项目接入时约定；未约定则保留“未配置定时提醒”，不把某个分钟数默认变成要求。
- Skill只是执行指导，不会自行醒来。需要宿主automation/heartbeat或持续可恢复执行；配置时使用宿主正式自动化工具，保留不变状态静默的意图，不能私建无限轮询。
- 执行者结束会话且无调度时，明确没有后台提醒能力。重新唤醒时读取task，核对问题仍未解决再行动。
- 对同一未变化问题只发一次已约定的提醒；之后保持waiting，除非用户另有提醒频率要求或有实质变化。
- 任何等待时长、发送成功或已读信息都不代表用户同意。受影响动作始终等待答复。

## 答复与双通道一致性

群、私聊和当前聊天使用相同需求/问题编号，答复写回原task。测试验收确认记录用户身份、消息/答复来源、需求、测试版本、范围与时间；“收到”只表示收到，不等于验收通过。需核对答复者是用户或其明确授权的人；普通群意见不自动成为产品决定。若各渠道答复相冲突，展示冲突并澄清，不能按最后读到的文字随意覆盖。

只有具备已授权的群读取/事件接入能力，才能从群自动收到答复；仅会发送不等于已配置收信。不能声称“我会持续监听群”但实际上没有运行机制。

## 发送状态

- 记录需求ID、阶段、版本/问题编号和message_id，用于去重和恢复，不建设新的全局消息平台。
- 发送超时结果未知时按原请求查证，不自动换key重发。
- 平台接受、回读成功、客户端格式、用户已读是不同结论；没有证据不混说。
- 群不可访问或权限不足时报告具体原因，不换身份绕过。通知失败不改变已通过的业务验证，但通知状态保持未完成。
- 群消息不能使用Agent主机上的本地文件路径作为唯一交付入口；提供接收人可访问的PR/预览/文档。无可用链接时明说尚缺访问入口。

## 消息模板

使用 [阶段消息模板](templates/im-message.md)。模板是内容结构示例，不是真实结果；发送前替换实际事实和可访问链接，按messenger流程润色并核对含义没有变化。
