# Mock 场景与编辑工作台

## 职责与数据

- 按模块/场景维护 `data/<module>/<scenario>/data.json`；提供浏览、编辑、保存、重置与导入导出。
- 每个场景说明用途、初始状态、响应、延时/故障和操作后变化。数据结构复用对应 API 契约，不另发明同名字段含义。
- JSON 表达数据与声明式模拟配置，不执行其中任意脚本。状态变化在模块的模拟实现中处理。
- 场景只包含合成或已获准公开的数据；不复制客户证件、生产凭据或原始标书进入仓库。

## 行为与保存

- 提交、重试、取消、刷新等行为按确认设计模拟；支持复位场景，保证测试可重复。
- 编辑未保存与已落盘状态可区分。浏览器刷新后的数据行为必须明确；不能把 localStorage 当作已保存到 Git 文件。
- 写文件能力仅属于本地设计工具，限制在场景目录并拒绝路径穿越，不成为业务后端。
- 契约更新后，检查受影响场景与模拟响应；不自动把所有失败场景改成成功。
- 测试覆盖数据保存/恢复、状态变化和错误模拟。通过 mock 测试不能宣称真实接口已完成。
